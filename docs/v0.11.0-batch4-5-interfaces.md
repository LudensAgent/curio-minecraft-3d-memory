## 1. 资源来源格版本（A）

库 `ResourceAnchorFact` 增加可选字段：

```ts
/** Source voxel cell evidence revision at the last confirmed observation. */
sourceCellVersion?: number;
```

语义与边界：

- 值来自同一 `worldId`/`dim`/`sourceCell` 的 `CellEvidence.revision`，由宿主在确认观察后读取体素图得到。
- 它不是 `observedAt`、不是保存批次号、不是全局 revision；不得用时间戳或任意 `0` 填充。
- 字段缺失表示“该记录没有可靠来源格版本”（旧迁移记录/旧磁盘记录），必须作为显式缺口报告，不能猜造。
- 不复制方块名称、属性或完整状态；资源名称仍由 `label` 表达，体素状态只存在于体素图。
- `ResourceSourceUpdate` 增加可选 `sourceCellVersion?: number`；缺省表示调用方没有可靠版本，保留原值或标记缺口。
- 快照持久化与恢复原样保留该字段；`confirmRevision` 的迟到 ACK 语义不变。

宿主资源索引规则：

- 资源 anchor 写入时记录来源格版本；`resourceIndexStatus()` 报告 `withSourceVersion`、`withoutSourceVersion`（缺口）与 `complete:false`。
- 同一格被更新观察时：只有新证据版本严格大于 anchor 版本才处理；同格仍是同类资源则更新 anchor 的 `observedAt` 与 `sourceCellVersion`，不再是资源则 `revokeResource`；版本不更新时忽略本次重复观察。
- 索引只由内存事实权威与当前内存体素格派生；不读取旧磁盘页重建，未落盘的撤销不会被旧页带回。
- 体素未驻留/未观察时只报告缺口，不撤销、不猜造空气。

## 2. 地点分页（A）

新增查询 kind：

```ts
{ kind: 'places'; dim?: string; tag?: LandmarkTag; label?: string;
  source?: NodeSource; includeGone?: boolean; after?: string; limit?: number }
```

- 直接使用 `FactStore.places()` 的有界分页，不在查询层读全量后排序切片。
- `after` 为稳定 id 游标，`total` 按过滤后的集合计数，`nextAfter` 只在仍有匹配记录时出现。
- 结果明确标记 `pageSource: 'memory'`：本端口回答内存事实权威，不冒充持久化冷页读取；当前实现没有逐页冷读地点接口，缺失时返回结构化缺口而不是全量载入。
- 既有 `nodes` 组合查询改为有界合并（逐流分页取最小 id），不再先拼接全部再排序。
- `snapshot` 的 places/resources/containers 计数必须按当前 `worldId` 过滤。

## 3. 能力报告一致性（A）

`buildMemoryHostCapabilities` 必须与 `dispatch` 的实际分发一致：

- 组合了 facts 时，`nodes`/`resourceAnchors`/`containerAnchors` 由 facts 回答；旧路线读面（fragments/traversals/edges/historyRoute/anchor/components/segments/portals）即使同时组合了旧 Store 也报告不可用，因为分发会返回 `unsupported`。
- 未组合 facts 且完整存在 fragments+topology+history 时，旧路线读面按其真实能力报告。
- 不通过恢复旧路线查询回退来消除矛盾。
- `plan` 块按同一组合判定；不把已退役入口报为可执行。

## 4. 保存后回收目标（B）

`WorkingSetManager.free(target?)` 的无目标行为保持不变（兼容），但宿主保存后换出必须显式给出容量目标：

- 目标由 `WorkingSetCoordinator`/`SharedSpatialSession` 按工作集上限计算，例如 `sections = floor(maxResidentSections * 0.75)`、`bytes = floor(maxResidentBytes * 0.75)`。
- 回收从 LRU 最旧开始，只淘汰到目标；pinned/dirty/未确认保存的 Section 仍由库拒绝。
- 保留“有限近期热页”由目标上限约束，不引入无界 hot set；导航执行依赖继续用显式 lease 保护。
- 报告 `evicted/rejected/capacity/target`，供 checkpoint 调度器与基准复用。

## 5. 缓存统计（B）

库 `WorkingSetStats` 增加累计只读计数（实现可放在 manager 内部，不影响事实权威）：

```ts
counters: {
  requestedSections: number;
  alreadyResidentSections: number;
  loadedSections: number;
  loadBytes: number;
  loadMs: number;
  evictedSections: number;
  rejectedSections: number;
}
```

- 只统计真实发生的 prepare/free 结果；不计查询、存活时间或重复刷新。
- 计数有界（饱和安全整数），不改变驻留、证据时间或保存语义。

## 6. 性能探针（B）

使用真实 SQLite、真实 manual 工作集、真实搜索与保存链路；身体移动可用 Fake，报告必须标明“非实机验收”。至少覆盖：

1. 首次冷读 512 格导航；
2. 相同路线热缓存再次访问；
3. 中途 checkpoint 后继续；
4. 来回访问/跨冷区切换；
5. 相关体素变化后的重新规划。

同一 session 累计预算，不通过新建 session 或放大预算掩盖问题。记录请求/已驻留/加载/淘汰 Section、重复加载、读取字节与耗时、A* 调用与节点/边/切片耗时、事件循环延迟、驻留字节、heap/RSS、保存 ACK、dirty 与队列增长。
