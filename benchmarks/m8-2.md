# M8.2 — H1 non-copy Section read: before/after

Before/after record for plan §M8.2 (audit H1). `VoxelMap` gains a trusted
internal read `sectionRef` (live `Readonly<Section>`, no deep copy); the public
`sectionAt` stays a defensive deep copy. `evaluateWalkStep` /
`evaluateGroundedWalkSegment` in `src/traversability/step.ts` now read through
`sectionRef` and copy the one evidence object that can escape (a BLOCKED
obstacle). `WalkRouteSearch` reaches this only through the evaluator.

**This is not an acceptance result.** It is a comparison against the M8.1
baseline (`baseline.md`), measured on the shared machine.

## Review correction (B19-M8-2-01/02)

After first review, `sectionRef` returns a narrowed `SectionRef` view
(`readonly palette`, `ReadonlyMap` evidence, read-only `key`; bit-packed
`Uint8Array`s shared under a call contract, not copied) instead of
`Readonly<Section>`; `SectionRef` is defined in `voxel-map.ts` and not
re-exported by any entry point (`dist/*/index.d.ts` has no `SectionRef`). The
evaluator now copies the mutable `BlockState` it hands to shape rules
(`resolveShape`, `neighborRead.cell`) and to `observedStates`, as well as the
escaping obstacle observation. Re-measured once after the correction (not a
full two-pass re-run): full corridor median 26.41 ms / p95 27.43 ms,
maxNodes=64 median 1.47 ms / p95 1.60 ms, `evaluatedSections=134` — same range
as the after passes above.

## Conclusion

- **Wall time**: full corridor ≈ 60 ms → ≈ 26 ms (≈ 2.3× faster; worst p95
  64.3 → 30.0 ms, below the B18 target of 55 ms); corridor control ≈ 59–60 ms
  → ≈ 25 ms (worst p95 67.1 → 29.9 ms, B18 target 50 ms); bounded
  maxNodes=64 ≈ 3.4–3.5 ms → ≈ 1.5–1.6 ms (worst p95 3.63 → 1.76 ms, B18
  target 2.9 ms). The improvement tracks `evaluatedSections`, i.e. the copy
  that was being paid per section cache miss, not the number of resident
  Sections.
- **Memory**: the per-search heapUsed high-water drops ~2–2.7× on the full
  corridor. No deep copy per section miss means no retained copies.
- **Semantics**: unchanged in evidence — all passes report the same `scale`
  column including `evaluatedSections`, `edgesUnknown`, search state, and the
  same route edge count; the focused suites (`tests/voxel-map.test.ts`,
  `tests/walk-search.test.ts`, `tests/step-evaluator.test.ts`,
  `tests/traversability-cache.test.ts`, `tests/land-route.test.ts`,
  `tests/route-verifier.test.ts`, `tests/water-validation.test.ts`,
  `tests/land-transition.test.ts`, `tests/walk-route-executor.test.ts`,
  `tests/entrypoints.test.ts`) pass with no test edits beyond the new
  `sectionRef` tests.
- **Sparse boundary row**: before median 0.072/0.153 ms (p95 0.073/0.156),
  after 0.071/0.059 ms (p95 0.073/0.061). The row is too small and too noisy
  to read a trend; its scale column (`edgesUnknown=4 evaluatedSections=6`) is
  unchanged in every pass.
- **Not measured** (out of scope for this card): `sectionAt` hot paths in
  `land-transition.ts`, `water/verify.ts` (their own direct `sectionAt` reads
  still deep-copy; the evaluator they call via `evaluateGroundedWalkSegment`
  now uses the trusted view), and route execution/route plan.
- Setup rows are untouched code and show only usual pass-to-pass noise.
